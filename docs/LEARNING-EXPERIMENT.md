# 从零学习模型与教材可读性实验

本实验的目标是发现人读教材时容易跳步、混淆或缺少前提的位置。它不是训练一个GPT，也不能用模型成绩替代真人学习效果。

## 实际训练了什么

`Learner` 是从空词表、空计数开始拟合的多项式朴素贝叶斯模型。特征为中文字符二元组及英文标识符，平滑系数固定为0.1，不加载预训练词向量、模型权重、联网语料或用户笔记。训练文档来自66个基础点、6节前置课和35节进阶课的讲解及伪代码。教程里的理解题、答案、题库参考解、用户学习记录均不进入训练集。

模型根据问题预测应阅读哪一课，并返回真实教材片段和哈希；它不生成自由文本解答。因此报告中的准确率叫**课程定位率**，不是“掌握率”“解题正确率”或“理解能力”。这是一个真实拟合的小型模型和提问回路，但不是具备通用语言理解能力的智能体。

20个固定探针保存在 `tests/learning-probes.json`，不作为训练样本。首次检查发现回车/终止符、getchar/EOF及整数除法等问题的定位失败或置信度较低，于是通过应用真实“C语言导师”界面提出3个独立问题，附对应教材原文。教师是现有GPT-5.6-Sol High，**不是从零训练的学生**。其回答保存在 [teacher-answers.json](learning-evidence/teacher-answers.json)，只有这3条合成测试问答，没有用户历史。

## 复现

只需项目支持的Node.js版本，无机器学习框架或GPU依赖：

```sh
npm ci
npm run learn:audit
node scripts/learning-experiment.cjs docs/learning-evidence/teacher-answers.json
```

第二条训练只读教材的模型，第三条加入已保存的真实教师回答。详细结果与可序列化模型写入 `tests/reports/`，该目录不进入源码发布包。教材SHA-256、证据片段哈希和每个探针的对错都在报告中，可定位版本变化。

若要重新调用自己的应用内导师（会使用本机Codex额度）：

```sh
npm run learn:ask
```

它在独立临时应用配置目录中启动Electron，最多提出3个困难问题，走与界面相同的 `CStudy.ask → studyAsk → Models.study` 路径；退出后删除临时配置，不碰正常学习记录。需要已登录且可用的 `gpt-5.6-sol` High权限。若系统不允许从受限终端启动GUI，可在正常应用中发送同样的问题并保存回答；本次验证采用的就是应用真实界面。调用失败会报告失败，不生成模板答案或伪造训练结果。

## 如何解释结果

[公开结果](learning-evidence/results.json)记录最终版本的空模型、阅读后、提问后对照。提问后数据针对已经发现的困难增加，因而是**适应后的结果，不是新的盲测成绩**。仍有一个未初始化/循环问题定位到相邻EOF课，说明词汇统计无法充分表达执行顺序。

没有为了让指标更高而修改探针目标、塞关键词或删掉难题。真正的修改依据是人可检查的解释：

| 位置 | 原讲解缺口 | 面向人的修订 |
|---|---|---|
| F01-10 | 声称赋值后“输出5”，省略输出语句；例子重复两遍 | 区分编译、赋值、printf、题意验证，删除重复展示 |
| F06-02 | “再补零”未说明由谁补、在哪一层 | 显示输入流与数组布局，区分getchar和fgets |
| F01-08 | 大小盒子的类比未展示信息怎样丢失 | 用明确标注条件的EOF=-1/无符号char例子推演窄化，说明不能推广到所有实现 |
| F02-01 | “转double”没有展开转换发生的位置 | 展示先计算、再转换、再保存，并对照两种强制转换位置 |
| 全部基础点 | 66处例子与步骤逐字相同，伪代码又重复一次 | 保留逐步讲解，另写真正的赋值/分支/循环伪代码 |

## 真人学习仍需验证什么

后续真人测试应让未学过C的人独立解释程序、预测没见过的输入、修复一个新错误并写出完整程序；记录卡在哪里、是否主动求助以及隔日能否迁移。不能只问“读懂了吗”。测试前应取得参与者同意、避免给出参考答案，并把辅助后完成与独立完成分开记录。本仓库目前没有这样的真人研究数据，不声称已证明教学有效性。
