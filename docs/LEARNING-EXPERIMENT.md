# 从零学习模型与教材可读性实验

本实验用课程定位错误寻找教材中容易跳步、混淆或缺少前提的位置，供可读性审查使用。

## 实际训练了什么

`Learner` 是从空词表、空计数开始拟合的多项式朴素贝叶斯模型。特征为中文字符二元组及英文标识符，平滑系数固定为0.1，不加载预训练词向量、模型权重、联网语料或用户笔记。训练文档来自66个基础点、6节前置课和35节进阶课的讲解及伪代码。教程里的理解题、答案、题库参考解、用户学习记录均不进入训练集。

模型根据问题预测应阅读哪一课，返回教材片段及哈希。报告的准确率是**课程定位率**，衡量匹配课程的能力。自由文本解释由已登录的 High 教师模型提供。

20个固定探针保存在 `tests/learning-probes.json`，仅用于评估，训练集与探针分开。首次检查发现回车/终止符、getchar/EOF及整数除法等问题的定位失败或置信度较低，于是通过应用真实“C语言导师”界面提出3个独立问题，附对应教材原文。教师为现有 GPT-5.6-Sol High，学生为上述从空计数拟合的小型模型。其回答保存在 [teacher-answers.json](learning-evidence/teacher-answers.json)，只有这3条合成测试问答，没有用户历史。

## 复现

只需项目支持的Node.js版本，无机器学习框架或GPU依赖：

```sh
npm ci
npm run learn:audit
node scripts/learning-experiment.cjs docs/learning-evidence/teacher-answers.json
```

第二条训练只读教材的模型，第三条加入已保存的真实教师回答。详细结果与可序列化模型写入 `tests/reports/`，该目录不进入源码发布包。教材SHA-256、证据片段哈希和每个探针的对错都在报告中，可定位版本变化。

若要重新调用自己的应用内导师（会使用本机Codex额度）：

```sh
npm run learn:ask
```

它在独立临时应用配置目录中启动Electron，最多提出3个困难问题，走与界面相同的 `CStudy.ask → studyAsk → Models.study` 路径；退出后删除临时配置，不碰正常学习记录。需要已登录且可用的 `gpt-5.6-sol` High权限。若系统不允许从受限终端启动GUI，可在正常应用中发送同样的问题并保存回答。已保存的三条回答来自应用真实界面；调用失败会记录错误。

## 如何解释结果

[公开结果](learning-evidence/results.json)记录当前教材版本的空模型、阅读后、加入已保存教师回答后的对照。6.3 复用三条历史教师回答，重新拟合并评估更新后的教材。提问后数据针对已经发现的困难增加，因而是**适应后的结果，不是新的盲测成绩**。逐题定位与置信度见结果文件，可检查相邻知识点之间的混淆。

修订依据是可检查的语义、示例与执行过程：

| 位置 | 原讲解缺口 | 面向人的修订 |
|---|---|---|
| F01-10 | 声称赋值后“输出5”，省略输出语句；例子重复两遍 | 区分编译、赋值、printf、题意验证，删除重复展示 |
| F06-02 | “再补零”未说明由谁补、在哪一层 | 显示输入流与数组布局，区分getchar和fgets |
| F01-08 | 大小盒子的类比未展示信息怎样丢失 | 用明确标注条件的EOF=-1/无符号char例子推演窄化，说明不能推广到所有实现 |
| F02-01 | “转double”没有展开转换发生的位置 | 展示先计算、再转换、再保存，并对照两种强制转换位置 |
| 全部基础点 | 66处例子与步骤逐字相同，伪代码又重复一次 | 保留逐步讲解，另写真正的赋值/分支/循环伪代码 |

## 真人学习仍需验证什么

后续真人测试应让未学过C的人独立解释程序、预测没见过的输入、修复一个新错误并写出完整程序；记录卡在哪里、是否主动求助以及隔日能否迁移。不能只问“读懂了吗”。测试前应取得参与者同意、避免给出参考答案，并把辅助后完成与独立完成分开记录。当前证据限于课程定位实验与内容审查；真人理解、独立编程和隔日迁移效果尚待上述测试。
